# Task 2: detector and policy improvement implementation plan

Status: documentation only, revised **2026-11-13**; lower priority than [task 1](../implementation-plan.md). Full methods and loss design: [policy-training-pipeline.md](../policy-training-pipeline.md). Task-1 implementation starts from the [Sol handoff](../sol-implementation-handoff.md).

1. **Collect reproducible onboard runs.** Reuse task-1 recording of normal-camera frames, gyro/accelerometer, VIO, cone observations, commands, actual steering, MCU application timestamps and timing. Add experiment lineage, map/reference/dynamics hashes and camera-calibration identity. Transfer artifacts to the Mac over Wi-Fi while stopped. Keep contact/aborted runs as failures even when their race score is discarded.
2. **Bootstrap cone detection.** Assume task 1 receives numeric YOLO cone detections. To supply real weights later, gather footage of the actual orange 200 mm × 150 mm cones on the wood hallway floor. Probe a prompted teacher and orange-color proposals on the Mac, manually verify a seed set, and expand labels using reviewed temporal/pseudo-label proposals. Do not assume generic YOLO weights include an adequate cone class.
3. **Fine-tune and evaluate.** Train a one-class YOLO26n 320 challenger against the available YOLOv5n baseline; investigate YOLO11n only if justified. Split by sessions into train/development/locked test. Validate recall, false positives and metric cone-center error, distinguishing visible rims from inferred centers. Export GPU FP16/float-I/O first; test CPU INT8 if contention/delegation warrants it. Evaluate exported artifacts and sustained Pixel latency before promotion.
4. **Improve dynamics identification.** Automate fitting beyond task 1's required initial speed/PWM, steering and braking tables. Preserve actuator calibration. Separate estimator/filter lag from motor response; validate on held-out maneuvers and include measured delay/loss.
5. **Optimize the heuristic policy.** Build a closed-loop simulator with measured dynamics/uncertainty. Search 5–8 parameters for path shape, pure-pursuit lookahead, yaw damping and speed. Use bounded CMA-ES offline, then conservative constrained Bayesian search over real runs. Mac planning generates each candidate's full path/speed profile while stopped; Pixel feedback begins at 50 Hz. Collision, validity and actuator constraints remain hard limits; compare clean completion time.
6. **Review and deploy from the Mac.** Extend task-1 validity review and transactional updates with candidate diffs, version/seed lineage and experiment comparisons. Activate matching policy/reference/dynamics artifacts while stopped, with rollback. Keep detector changes separate from policy changes and revalidate the map after perception changes. Uncertain contact labels cannot approve a clean run.
7. **Consider a learned residual later.** Only after the tuned heuristic and sufficient diverse data exist, test a small bounded residual against the same baseline. Require closed-loop and on-phone evidence before replacing the simpler controller.

Expected tools: dataset validator/label-review exporter, model-family training/export adapter, dynamics fitter, closed-loop simulator, parameter-search runner and experiment report generator. Reuse `tools/maxbot/dataset.py` and the current trainer's provenance approach, replacing its YOLOv5-specific contract through explicit adapters. Do not implement these tools or train models in the current documentation phase.

Acceptance: every artifact has provenance; failure data is retained; exported-model accuracy and full-system latency are measured; repeated candidate trials improve clean completion time without unsupported reliability claims; settings/model updates require no APK reinstall within the app's supported policy/model contracts.

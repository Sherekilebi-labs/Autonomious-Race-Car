## M1–M6 software milestones

- **M1:** Runtime actuation uses a separate priority-4 nominal 5 ms motor task. The saved runtime PID law (including its nominal 0.005 s gains), lookup table, DC H-bridge behavior and PWM mapping are preserved. An 8-entry command queue and 64-entry nonblocking application ring are bounded. Absolute expiry is rechecked after validation/queueing and during actuation. Local expiry, fault, application loss and motor overruns are recorded. A separate stop task/socket (4243) authenticates the stop-only role, latches zero outputs, and acknowledges after application without changing the phone owner or telemetry route. Stop IDs have a 5 s boot-local freshness bound and a 32-entry replay cache. Reset is phone-owned, stopped-only and remains disarmed.
- **M2:** Independent Wi-Fi TX/RX, newest output handoff, explicit zero application acknowledgement on motion-mode/epoch transitions, original browser event/deadline forwarding, four-timestamp clock mapping and causal application accounting. Controller work executes outside the supervisor monitor. Capture timing stays unavailable; image-available, policy-output and state-age measurements have distinct labels. Camera, VIO, raw IMU, optional video/recording and control use bounded independent paths. Raw IMU does not become a second pose covariance or an integrated speed sensor.
- **M3:** ARCore enumerates rear-camera stream/FPS IDs and reports actual CPU intrinsics/timestamp source. Calibration binds the selected stream; pitch/yaw, sensor rotation, bias, lever arm and empirical state bounds remain unmeasured. Native strided packing and normalized letterbox preprocessing build independently of MPC (MPC is opt-in). Model manifests gate exact tensors, dtypes, quantization, decoder and hash. YOLOv5n and explicitly exported YOLO26n end-to-end XYXY contracts are implemented; unsupported layouts/operators fail closed. No trained cone weights were found or synthesized. A box base is explicitly an inferred rim; its radius-corrected center still requires independent scene validation.
- **M4:** Separate reviewed dynamics tables and schemas, full-rate measurement logging, bounded one-sided scout segments with hidden cones retained as priors, measured-map freeze, stopped Mac SciPy/SLSQP multiseed bicycle planning and independent continuous footprint validation. Search candidates are retimed against steering, lag, grip, acceleration, braking and floor constraints and ranked by finish time. Planning is a cancellable subprocess; a changed stopped snapshot/dependency discards results. The inherited 150 mm clearance is retained. Local optimizer failure never asserts global infeasibility.
- **M5:** `cone_slalom_v1` follows a frozen reference using the specified pure pursuit plus yaw damping, bounded progress, measured feedforward/PI anti-windup, actual elapsed ticks and bounded application-time propagation. No duplicate curvature feedforward. Ordered right/left/right/left scoring checks swept geometry in the frozen row frame, includes rotated rear clearance, and separates finish crossing from subsequent rest. Contact remains operator-reviewed; failure data is retained.
- **M6:** Status-only phone startup, Wi-Fi socket binding, authenticated expiring AP discovery, reconnect without arming, bounded JSON/model/reference staging, closed-schema/hash/capability checks, warm-before-commit atomic active-set pointer and rollback. Restart warms the active set but discards a reference whose localization/map session cannot be restored. The Mac console exposes frozen-course planning, artifact revision review, explicit activation, benchmark markers, Wi-Fi run export, manual deadman, persistent direct stop status and contact review. Native algorithm additions still require an APK update.

These describe implementation, not device or physical validation. Module-specific test/build results and the exact outstanding commissioning work are recorded in `deployment-readiness.md`.
